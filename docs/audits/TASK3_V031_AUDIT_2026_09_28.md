# Task 3 v0.3.1 audit — September 28, 2026

## Verdict

The current task is substantially stronger than the version covered by the previous audit. I found no new blocking answer leak, clinical-label defect, or grader defect explaining the four runs retained as reasoning failures. Each of those four runs has at least one defensible failure under the public rules and records it actually received.

That conclusion is narrower than certifying every case by independent clinical review. The latest model batch tested **v0.3.0**, not v0.3.1. Its raw result is **4/10**. The **4/8** figure is a useful, retrospective reasoning-only analysis; it does not establish the final v0.3.1 task's targeted 2–7 passes in ten trials. One excluded attempt was a valid budget-limited failure under the adapter's own classification, not an infrastructure error.

The task measures cohort-wide record reconciliation, retrieval/coverage, clinical classification and calibrated abstention. It does not establish that the agent's explanations or supporting citations are substantively correct, and the repeated case families are not 800 independent reasoning tests.

## Findings and recommended changes

### 1. Report the pilot denominators and version separately

**Priority: medium; reporting validity.** `chartr_task3/README.md:27` and `PROGRESS.md:11` describe the adjusted 4/8 result as inside the 2–7-of-10 target. Keep three distinct statements:

1. v0.3.0 raw benchmark outcome: **4 passes / 10 attempts**.
2. Retrospective analysis: four defensible model failures, one wording-affected failure, one output-budget failure.
3. v0.3.1: free verification passed; a new frozen ten-trial model batch has not yet been evaluated here.

`PQ8ap5i` is logged as `output_truncated`, `validity: valid`, consistent with `anthropic_agent.py:113–115`. Excluding it from a study of reasoning errors is reasonable if stated explicitly, but it must remain in the raw result. The model exceeded the allowed response budget while building one large command; this is different from an API outage or corrupt evaluation.

Clarifying policy and raising the output cap changes the tested condition. Before a new paid batch, freeze v0.3.1, the adapter, model identifier, budgets and exclusion rules. Obtain authorization for that batch. Do not retroactively upgrade the old runs to v0.3.1.

### 2. The Git preflight can succeed when Git fails

**Priority: low; reproducibility safeguard.** `qa/task3_preflight.py:29–30` reads subprocess stdout without checking the exit codes. In the audit archive, which has no Git repository, it reports a clean checkout, prints an empty commit and exits successfully. The fixture/version/digest checks still work.

Require successful Git commands and a nonempty commit before claiming checkout provenance. This does **not** invalidate the current ten trials: their individual task hashes were independently checked against the release. No implementation change was made during this audit.

### 3. Do not overstate the measured reasoning or independent validation

**Documented limitations, not newly discovered scoring defects.** `chartr_task3/tests/grade.py:108–110,149–153` checks that citation IDs are allowed and that explanation text is nonempty. It does not check whether a citation proves the decision or whether the explanation is correct. In particular, clinic-wide records without a patient subject can be admissible even when irrelevant to the conclusion. Passing means correct structured dispositions and missing-evidence codes, not a verified clinical rationale.

The rules engine is an independently written calculation, but it also consumes authored case facts/overrides (`qa/task3_rules.py:48,122`). Agreement with authored answers cannot by itself establish that the rendered records communicate every necessary fact. The saved blind-review decisions are valuable additional evidence. The final review covers 60 patients/240 decisions, with all linked charts supplied; it is not an independent full-cohort retrieval exercise or review of all 800 decisions.

The zero-tolerance score is an intentional aggregate-reliability test. Repeated errors in three instances of one family should be described as one recurring reasoning failure, not three independent discoveries of model weakness.

### 4. Correct two descriptions of what the model did

**Priority: low; attribution accuracy.** README lines 15–16 say `CJ4ZKQH` answered not-an-issue to every follow-up candidate. It did not: among its explicit follow-up items were 13 not-an-issue, one confirmed and one cannot-determine. For example, it recognized the case with an explicit twelve-month reminder. The accurate description is that it treated guideline-based follow-up as requiring a chart-specific recommendation and missed many candidates.

The descriptions “ignored outside care” and “took the MAR over” also infer more of the model's reasoning than the trace establishes. Several decisive note phrases never appear in the model-visible tool results; its scripts filtered the records before displaying selected content. These are valid failures of coverage/reconciliation in this agent task, but some may be failures to retrieve or retain the relevant evidence rather than conscious rejection of evidence the model read.

## Leak and isolation assessment

No direct answer leakage was found in the reviewed public surface:

- The agent image copies the public CLI and two public documents. The framework, authored answers, generator, private grader, baseline, review answer keys and reference solution are outside that image's copied files and evaluated filesystem.
- The agent and clinic are separate services. The service's immutable clinical sources and writable item state are distinct; the agent has no database access, admin/reset route, host mount or Docker socket through the supported environment.
- The controller stops agent actions and collects the service's frozen state. The verifier runs separately and checks controller attestation, initial fixture identity, audit continuity and source integrity. An agent-written replacement snapshot does not become grading evidence.
- The fresh boundary probe could not access private files, source-write/admin routes, credentials or the Docker socket. It planted a forged local snapshot; trusted collection still returned the real 4,482-source service state, frozen with zero service faults.
- The public examples use placeholders. No private family/variant/expected-answer labels were found in the fixture data. Ordinary patient identities and clinical status facts remain public, appropriately.
- All **1,037** laboratory accession values are unique across distinct result triples; the earlier accession-collision defect is fixed. Cross-chart citation permission is now derived from the attested clinical records and matches the published rule.
- All **470** readable note texts agree with their encoded attachments. The 14 F3 patients no longer receive an explicit stage label that bypasses their history-based inference.
- The saved model tool commands/results did not reveal use of private expected-answer, generator, verifier or reference-solution files in the paths scanned.

This is a bounded implementation and runtime audit, not a proof against every possible exploit. Repeated templates remain recognizable; using a reusable script to apply a correctly inferred rule is legitimate task solving, not by itself an information leak.

### Why the four retained failures are supportable

**5XayigW — care outside the clinic and a dose conflict.** Renee Salazar (p08) reports a second injection at Eastside and a third scheduled there; requests for the outside records remain unanswered. Olivia Grant (p13) reports a syphilis blood test at her PCP during the relevant follow-up month, with no returned record. Sofia Ingram (g138) and Bianca Rasmussen (g139) report remaining injections at named outside clinics, also with records requested but unreceived. This is positive evidence of possibly adequate care, so confirmed inadequacy/overdue status is overconfident under the published `OUTSIDE_RECORD_NOT_RECEIVED` rule.

Andre Castillo (p06) has a MAR recording 2.4 MU, but a pharmacy entry and pharmacy note document only one 1.2-MU syringe released, with no second syringe on the cabinet log. No governing author correction resolves the discrepancy. The task's public rule treats other conflicts as unresolved. An omitted item therefore wrongly asserts not-an-issue.

**ALwrnZf — uncertainty must propagate.** Walter Greene (p16) has a specimen in the final follow-up window whose collection identity names him while the accessioning identity names Thao Nguyen. The run recognizes `MISFILED_RESULT = cannot_determine` but treats follow-up as settled. If the specimen's patient is unresolved, it cannot establish that Walter completed that required collection. `FOLLOW_UP_OVERDUE = cannot_determine / UNRESOLVED_SOURCE_CONFLICT` is the supported answer.

**T9WouCF — the disputed date changes the answer.** For Farah Yamamoto (g076), Kofi Wainwright (g077) and Tomas Moreno (g078), a clinician other than the MAR's author disputes the administration date in a progress note. This is not the same-author correction that the public rule lets supersede a record. Their follow-up specimen fits one date's window and misses the other; the difference is not an exact-boundary artifact. For example, Farah's December 9 specimen fits the January 1 anchor but falls before the December 29 opening associated with a January 28 anchor. The date conflict therefore matters to the decision. Omitting the follow-up issue asserts more certainty than the records permit.

**snDgxNq — a potentially relevant specimen is filed elsewhere.** Carmen Grimes (g017), Daniela Donovan (g019) and Alicia Mbeki (g021) are each identified on an accessioning entry for a timely specimen filed in a different patient's chart. That chart's collection identity conflicts with the accessioning identity. The model can neither count the specimen definitively nor conclude definitively that these patients lacked timely testing. The required abstention follows from a documented cross-chart possibility, not an unsupported hypothesis about missing care.

Its separate p11/g132/g133 errors concern pending, unrejected specimens already collected within their windows. The v0.3.0 wording was less explicit about judging rejection as of the evaluation time. The new wording resolves that concern; applying it retroactively would overstate the strength of those three errors.
