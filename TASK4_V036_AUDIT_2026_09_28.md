# Task 4 v0.3.6 audit — September 28, 2026

## Verdict

The task has a credible clinical-record and ECG-analysis objective, and its private evaluation boundary held in fresh Harbor checks. I found no direct exposure of the private answer key, reference solution, machine-reading table or grader to the evaluated agent.

I would **not yet describe every remaining failure as a clean, validated reasoning error**. The numeric ECG tolerances and categorical decisions are not consistently aligned; one such problem affects the actual latest pilot. There are also detectable case-generation patterns and a newly reproduced service-concurrency defect that can go unreported as an infrastructure fault.

The latest batch's arithmetic is correct: **1/10 against its original v0.3.5 key, 4/10 rescored against v0.3.6**. This audit does not replace that with a new pass count. Several failures are well supported, but the present evidence does not justify the README's blanket statement that all six remaining failures are genuine.

## Findings

### P1 — Accepted QT measurements cross the mandatory review threshold

The public clinic memo requires review at **Bazett QTc >=500 ms** (`qa/build_task4.py:414–417`, rendered into the public clinic documents). The fixed expected item set requires a QT-safety item for the following ECGs, while both their review-item numeric tolerance and interpretation tolerance accept readings below 500:

| Patient / ECG | Accepted QTc range, ms |
|---|---|
| 10013049 / 108018814 | 488.5–601.7 |
| 10004422 / 106885519 | 489.2–589.2 |
| 10012853 / 101515306 | 491.3–592.5 |

This affects **`rfo6TJY`**. Its saved interpretation of 108018814 is **496 ms**, which the key accepts. Its explanation explicitly says that this is below the memo's 500-ms prescriber-review threshold; it therefore omits the item and fails identification. Calling this simply a failure to reason about the threshold is unsupported: its action follows its accepted measurement.

This does not prove that the physiological QTc is below 500 or that every algorithm reporting 496 is clinically accurate. It shows that the benchmark grants that measurement tolerance while using a stricter, separate decision boundary. If the intended error is ECG measurement, the scoring must express that consistently.

**Recommendation:** use independently adjudicated measurement uncertainty to align the numeric and categorical specifications. Either select/adjust tracings with a sufficient decision margin, or permit the associated disposition when an accepted reading crosses the threshold. Do not add a one-run exception or simply squeeze the tolerance to reject 496 after seeing this pilot.

Relevant implementation: `qa/build_task4.py:563–568`; `qa/task4_interp_truth.py:79–91`; `chartr_task4/tests/grade.py:79–102`.

### P1 — Serial QT-change labels use narrower uncertainty than the accepted measurements

`qa/task4_interp_truth.py:161–166` derives required/allowed 60-ms changes from the **unpadded reader values**, while individual QTc fields accept padded ranges. Consequently, readings that both satisfy the key can imply a change that the comparison grader rejects.

Reproduced directly against the actual grader:

| Current / prior ECG | Individually accepted QTc values | Computed change | Key behavior |
|---|---|---|---|
| 104821039 / 107149156 | 510 / 480 ms | +30 ms | Requires `QTC_INCREASE_60`; rejects no change. |
| 102172660 / 105362569 | 450 / 500 ms | −50 ms | Requires `QTC_DECREASE_60`; rejects no change. |
| 103036945 / 102616671 | 450 / 380 ms | +70 ms | Forbids `QTC_INCREASE_60`. |

An all-correct unit fixture scores 1; changing only these readings and the corresponding logically derived change makes the comparison component fail. Ten required latest/prior pairs have such tolerance-boundary mismatches. These are grader unit fixtures, not attempts to forge controller evidence, and acceptance by a numeric spec is not itself physiological adjudication.

`rfo6TJY` also fails the first comparison. However, its actual trace measured the prior at about **517.6 ms**, outside the prior key's 392.5–489.7 range. Therefore **do not automatically promote this run to a pass**: its prior reading still needs adjudication. The general tolerance inconsistency is independently reproducible even without that run.

**Recommendation:** define a joint measurement/comparison rule before more pilots. Require a change only when the accepted uncertainty supports it robustly; otherwise allow the plausible alternatives, or collect prior measurements explicitly and grade their relationship consistently. Add regression tests for accepted numeric pairs crossing each categorical boundary.

### P1 — Concurrent valid reads can fail without an evaluation-error flag

The clinic uses a threaded HTTP server, but its state connection uses SQLite autocommit (`store.py:47`). Request processing calculates `MAX(audit.seq)+1` and later inserts that sequence without an encompassing transaction (`store.py:108–127`). Simultaneous requests can choose the same sequence number.

Two reproductions:

- Direct public-route probe, 40 `/ecg` reads with eight workers: **35 `UNIQUE constraint failed: audit.seq` exceptions**, five recorded successes, **`faults: 0`**.
- Fresh Harbor HTTP probe: **30 remote-disconnection errors out of 40 reads**, with the final trusted snapshot still reporting **`faults: 0`**. Harbor returned a valid reward 0 rather than an evaluation error. The probe deliberately submitted no clinical answers, so reward 0 itself is expected; the problem is that the service errors remain invisible to evaluation validity.

The audit insert is outside the fault-recording exception handler. This can penalize a legitimate agent that parallelizes retrieval, even though public tool documentation does not forbid concurrent reads.

**Recommendation:** make request state changes and audit sequencing atomic/serialized, and record failures of the auditing transaction as infrastructure faults. Test concurrent reads and writes through HTTP, not only sequential direct calls.

I found **no trace evidence that this defect caused the latest ten pilot outcomes**. Their snapshots report zero faults; the examined tool results do not contain these transport/audit failures. This is a newly demonstrated reliability risk, not grounds for silently discarding existing runs.

### P2 — “Three independent readers agree” overstates the actual labeling procedure

The implementation uses field-specific reader selection, not uniform three-reader agreement:

- QRS uses the machine and global method only (`task4_interp_truth.py:70–72`). The saved NeuroKit QRS value falls outside the graded range on **28 of 37 required ECGs**.
- The global method shares NeuroKit's lead-II R-peak detection (`task4_interpret.py:77–80`), so those two methods are not fully independent.
- QTc selects anchors and excludes other readings by distance from them; edited QT traces do not retain a machine QT measurement of the edited signal (`task4_interpret.py:200–202`).
- For ECG **108195884**, saved PR values are machine **136**, NeuroKit **131**, global **220 ms**. The key forbids first-degree AV block because the first two are <=160, despite the third reader's disagreement (`task4_interp_truth.py:128–133`).

None of this proves that NeuroKit's broad QRS measurements or the global PR are correct. Rejecting an unreliable algorithm for a particular field can be sensible. It does mean that “grade only where three independent readers agree” is not an accurate assurance of unambiguous clinical truth.

**Recommendation:** document the actual eligibility/adjudication rule for each field, validate excluded readers rather than silently treating their disagreement as consensus, and obtain blinded expert adjudication of disputed ECGs. Preserve annotated fiducials or review notes and the accepted uncertainty. Model-vote frequencies such as “14/15 runs read it correctly” are supporting observations, not a clinical gold standard.

### P2 — Case/control separation is reduced, but not eliminated

The existing QA checks ten individual aggregate features and permits AUCs up to just under 0.80. This does not establish that cases cannot be distinguished by other public structural features.

Using only records returned through the service's public read routes:

- **Two Cardiology Clinic visits fewer than 60 days apart** identify **six of 18 case patients and zero of 51 living controls**: 10004457, 10013049, 10015272, 10019385, 10022880 and 10039831.
- This has a direct generator explanation: routine visits advance by **60–130 days**, while case-specific fixed visits can break that rule (`qa/build_task4.py:237–265`).
- **Maximum single progress-note length** has case/control AUC **0.835**. Existing QA checks total note length, not this feature.
- Routine progress notes have five content lines plus the signature section. Added case-specific prose creates a sixth content line; this flags five cases and three controls. It is an enrichment signal, not a perfect label.

These shortcuts can prioritize likely cases without understanding their clinical evidence. They do **not** identify every issue or solve the 37 ECG interpretations, and some association between clinical complexity and record size is natural. The deterministic visit-gap floor is the clearer artificial signal.

**Recommendation:** generate irregular visit spacing and varied note structures for controls as well as cases, through the same process. Test metadata-only baselines and combinations of features, using held-out generation seeds where feasible. Avoid claiming “cannot be told apart” on the strength of the current marginal AUC checks.

## Are the post-pilot changes principled?

Many changes have a defensible general rationale:

- Accepting charted rhythm, clinical notes and older ECGs as AF evidence corrects an overly narrow evidence whitelist.
- The v0.3.6 dysrhythmia change still requires an AF-establishing record; the broader codes can only accompany it. It does not let a nonspecific dysrhythmia code alone establish AF.
- Accepting an eligible start-visit note as a follow-up trigger aligns grading with the public tool contract.
- Interval tolerance widening, indeterminate axis handling, and allowing genuinely ambiguous rhythm alternatives are appropriate responses to measurement/labeling uncertainty when applied consistently.
- The vascular-disease interpretation is supported by the named guideline's inclusion of coronary disease with prior intervention/revascularization. Its anticoagulation thresholds also match the task's sex-specific scoring approach. [2023 ACC/AHA/ACCP/HRS guideline](https://www.jacc.org/doi/10.1016/j.jacc.2023.08.017)

But these changes need a clearer distinction between **defect correction**, **task redesign/calibration**, and **test-set adaptation**:

- Adding AF explicitly to clinic histories in v0.3.2/v0.3.4 and excluding deceased patients' ECGs change what is tested. They are legitimate difficulty calibration, not retrospective proof that older failures were unfair.
- Narrowing rhythm conflicts to notes changes the public task definition. The earlier policy's nursing-chart interpretation was plausible; those earlier flags should not be presented as pure model error under the later definition.
- Rhythm exceptions keyed to individual ECG IDs and PR/axis margins introduced after seeing failures require independent adjudication. A general code rule is better than a run-name exception, but it does not by itself remove selection bias.
- The saved history documents why changes were made, which is good. It does not provide a complete blinded cardiologist adjudication trail for every disputed field. There is no basis here to infer deceptive intent, but the resulting pass rate remains a development/calibration result.

Use fresh trials against a frozen final key and configuration after resolving the findings. Report **1/10 raw v0.3.5** and **4/10 retrospective v0.3.6 rescore** separately. Do not call the latter an independent confirmation batch for v0.3.6, and do not tune tolerances simply until the target rate is reached.

## Information boundary and environment

Fresh checks support the intended separation:

- The agent build allows only the public CLI/docs and pinned analysis dependencies. Private expected answers, reference readings, grader and generator are not copied into the evaluated image.
- The clinic image receives the assembled source database and ECGs. The synthetic overlay is a build-stage input, not an agent-readable directory. The agent cannot access `/data`, `/state`, private service files or the Docker socket through its filesystem.
- The provider rejects bind mounts, attests the source digest, stops agent actions before collection, and collects the frozen snapshot through the trusted service channel. The verifier is separate.
- A forged agent-local snapshot did not replace service evidence in the boundary probe.
- All 208 served ECG headers have their comment lines removed. The private machine measurements are not shipped. Original public study IDs remain, but the tested agent network could not reach an external IP or PhysioNet; no online machine-label retrieval bypass was demonstrated.
- Source writes/admin routes and credential exposure checks passed. No secrets were printed or added to artifacts by this audit.

The concurrency finding qualifies the service's **failure reporting**, not the isolation of private answers. A failed transport can currently be omitted from the trusted audit trail even when the captured final state itself is genuine.

5. Correct current-state documentation and fail-closed preflight behavior.
